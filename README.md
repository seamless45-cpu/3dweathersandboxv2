# MeteoLab: 3D Weather Sandbox

A physically grounded 3D atmospheric sandbox: convective cells, supercells, tornadoes, lightning
and radar, simulated live in the browser.

## Install it as an app

MeteoLab is a progressive web app. Visit the deployed page and use the **Install** button in the
bottom strip (or the browser's own install control) to add it to your desktop or home screen. Once
installed it runs in its own window, works offline, and can be launched straight into a scenario
from the manifest's shortcuts.

There is nothing to fetch at runtime: the whole simulation is client-side and every script is
inlined into the document, so the service worker only has to cache that one document plus the
icons and manifest.

### How the PWA is wired

| Piece | Where it lives | Notes |
| --- | --- | --- |
| Web app manifest | `public/manifest.webmanifest` | Copied to the deployment root by the build |
| Service worker | `public/sw.js` | Hand-written; network-first navigations, cache-first assets |
| Icons and screenshot | `public/icons/` | Generated by `npm run icons` |
| Client plumbing | `src/pwa.ts` | Registration, install prompt, offline and update state |
| Install / offline strip | `src/ui/InstallPrompt.tsx` | The bottom-centre affordance |

The worker is a separate file rather than a bundled module because the single-file build inlines
every module into `index.html` — a worker generated from a module would be inlined into the page
and never registered as a worker.

Caching strategy: **navigations are network-first**, so a returning visitor always gets the current
build when they are online, falling back to the cached document offline. Assets are cache-first,
keyed to a versioned cache name. Bumping `VERSION` in `sw.js` ships a new build, and the app shows
a "new build is ready" prompt that activates the waiting worker on request.

## Develop

```sh
npm ci
npm run dev            # Vite dev server; the service worker registers on localhost too
npm run icons          # regenerate the PWA icon set from scripts/generateIcons.mjs
npm run validate:pwa   # manifest, icons, worker runtime and the install-state machine
npm run validate:shaders
npm run bench -- 120 supercell_alley 12        # headless physics benchmark
node scripts/runLagSpikes.mjs 2400 supercell_alley 12   # per-frame cost distribution
```

`runLagSpikes.mjs` reports the p50/p90/p95/p99 of the physics step rather than just a mean,
because a mean cannot tell "this build is slower" apart from "this build hitches every eleventh
frame". A healthy build has p95 close to p50; a wide gap means frame cost is bunched into a few
expensive steps. The script also buckets by frame range so JIT warm-up is separated from steady
state, and prints a spike ratio for a quick regression check.

## GitHub Pages

GitHub Pages publishes the repository root from `main`. Generate the deployable build with:

```sh
npm run build:pages
```

Commit the changed root files afterwards. `scripts/copyPagesBuild.mjs` mirrors the whole of `dist/`
to the repository root — not just the HTML — because a PWA needs its manifest, worker and icons
beside the document that references them. Confirm the deployed tree with:

```sh
npm run validate:pages
```

There is no browser in the build environment, so the PWA is verified by
`scripts/validatePwa.mjs` (manifest schema, real PNG dimensions against declared `sizes`, precache
completeness), `scripts/testServiceWorker.mjs` (the worker executed in a simulated
`ServiceWorkerGlobalScope`: versioning, cache eviction, network-first navigations, cache-first
assets, offline fallback) and `scripts/testPwaClient.mjs` (the install-state machine: prompt,
acceptance, persisted dismissal, iOS manual install, connectivity events). The Vite source template is `app.html`; the build bundles
the app into one self-contained HTML file and rewrites its asset references to be relative, so the
same document works at the origin root and under `/3dweathersandboxv2/`.

## Controls and audio

- Desktop: move with WASD or the arrow keys; ground movement is set to 120 km/h. Drag the scene to look around.
- Mobile: use the on-screen joystick; keyboard movement is disabled.
- Sound is opt-in from the toolbar. Wind, rain, and distance-delayed thunder are synthesized locally in the browser, so no audio files or network requests are needed.
